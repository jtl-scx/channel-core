# Channel API models

Rules for the models in `src/Client/Model/` and their tests in `tests/Client/Model/`.

The models are written by hand. No tool generates them. The header "auto generated by OpenAPI
Generator" in the existing files is outdated. [MUST NOT] copy it into a new file. [SHOULD] replace
it in a file you change for another reason.

## Source of truth

The models follow the Channel API specification. The published OpenAPI file is
<https://developer.jtl-software.com/openapi/marketplace-channels/channel.json>. A schema is at
`components.schemas.<Name>` in that file.

- [MUST NOT] add a property, a type or an allowed value here that the specification does not have.
- [MUST NOT] change the specification to fit a model. The specification changes first, then the
  model.

## Models

- Namespace `JTL\SCX\Lib\Channel\Client\Model`. One class per file.
- The class name is the schema name in the specification. The file name is the class name. Some
  schemas have no class with the schema name, see
  [Schemas without a class and inline objects](#schemas-without-a-class-and-inline-objects).
- A model does not declare `strict_types`, like the existing ones. With `strict_types`,
  `mb_strlen(null)` on a required property that is not set throws a `TypeError`, so `valid()`
  throws instead of returning `false`. `WorkEventCommand` and `AbstractEmitEventCommand` call
  `valid()` at runtime.
- A model implements `ModelInterface`, `ArrayAccess` and `\JsonSerializable`.
- Copy the structure of an existing model. `AllowedValue.php` is a small example, `Address.php`
  has an inline enum (`gender`), `Attribute.php` has lists of models.
- Every property has an entry in each of these static arrays, in the same order as the
  specification: `$openAPITypes`, `$openAPIFormats`, `$attributeMap`, `$setters` and `$getters`.
- Keep the accessor methods (`openAPITypes()`, `openAPIFormats()`, `attributeMap()`, `setters()`,
  `getters()`, `getModelName()`), `DISCRIMINATOR`, `$openAPIModelName` and `$container`. Keep
  `jsonSerialize()` and `__toString()` too: a request class sends `(string)$model` as its body.
- A type is a PHP scalar (`string`, `int`, `float`, `bool`), a `\DateTime`, a fully qualified
  model class, or one of these with `[]` for a list, for example
  `\JTL\SCX\Lib\Channel\Client\Model\AllowedValue[]`. Put the `format` of the specification in
  `$openAPIFormats`, or `null`. More cases:
  - A binary file (`format: binary`) has the type `\SplFileObject` and the format `binary`
    (`InvoiceUpload.php`, property `document`).
  - A `$ref` to an enum schema has the enum class as type (`Order.php`, property `orderStatus`).
  - A `oneOf` has no type that `ObjectSerializer` can build. Ask before you add one. The one case
    in use, `SellerEventListEventListInner` (property `event`), has one class with the properties
    of all variants: `SellerEventListEventListInnerEvent`.
  - Key and value in `$attributeMap` can differ. Copy the name from the specification exactly
    (`ReportRequestOptions.php`, `'resultsAsChannelEvent' => 'ResultsAsChannelEvent'`).
- The constructor reads each property with `$data['name'] ?? null`. Use the default of the
  specification instead of `null` when it has one (`AllowedValue.php`, `sort`).
- A required property has a non-nullable getter and setter type. An optional property has a
  nullable type (`?string`). The setter returns `$this` and its return type is the class.
- A list property has the getter and setter type `?array` (or `array` when required). The
  `Model[]` type goes in `$openAPITypes` only.
- The model keeps its values in `$container` only. Do not add other state.
- A model needs no registration. `ObjectSerializer` reads `$openAPITypes`. A seller event needs
  more than its model: see "Wiring a seller event" in the `AGENTS.md` of the repository root.
- Do not add business logic. A model holds data and validates it.

### Schemas without a class and inline objects

- A schema that is only a scalar with constraints (for example `SellerId`, `OfferId`,
  `CategoryId`) has no class. The property that refers to it gets the scalar type, and its
  constraints go into the validation of that property.
- `allOf` becomes one flat class. It has the properties and the required lists of all parts, in
  `allOf` order. [MUST NOT] use `extends`.
- Do not write a class for a schema that the specification uses only as an `allOf` part (for
  example `EventSellerRelated`, `Product`, `ReportRequest`). Some such parts already have a class
  (for example `OrderShipping`, `Refund`); keep them. A part that the specification also uses
  directly has its class, for example `Address` and `OrderBuyer`.
- A schema that is only a list (`ReportSellerInventory`) has no class.
- An inline object has no schema name in the specification.
  - When it has a `title`, the class name is the title (`OrderShippingPosition`,
    `ChannelNotificationReference`).
  - Without a `title`, the class name is the name of the parent class plus the property name in
    PascalCase, and `Inner` at the end when it is the item of a list
    (`AttributeConditionalMandatoryByInner`, `OrderStatusOrderItemsInner`,
    `OrderShippingPositionShippedFrom`).
  - [MUST NOT] invent another form.

### Validation

Validation lives in `listInvalidProperties()`. `valid()` returns
`count(listInvalidProperties()) === 0`.

For every constraint in the specification, add a check with a message that says what is wrong:

- Required property: `'name' can't be null`.
- `minLength` and `maxLength`: `mb_strlen()`.
- `pattern`: `preg_match()`. The specification stores the pattern without delimiters
  (`'^\w{1,50}$'`). Wrap it in `/.../`, escape each `/` inside it and double the backslashes in
  the double-quoted string: `"/^\\w{1,50}$/"`. Without the delimiters PHP warns and returns
  `false`, so `valid()` rejects every value. Copy `AttachmentData.php` (`sellerId`).
- `minimum` and `maximum`: a comparison.
- `minItems`: `is_countable()` and `count()`. Never compare the array itself with a number. The
  message is `invalid value for 'x', number of items must be greater than or equal to 1.`
  - Required list: copy `OfferListingFailed.php` (`errorList`).
  - Optional list: copy `AdditionalOrderDataGroup.php` (`values`). The check starts with
    `!is_null($this->container['x']) &&`.
- `maxItems`: [MUST NOT] write a check. The API enforces the limits. Keep the existing checks on
  `channelSpecificAttributeList` in `ShippingRules` and `SellerShippingRules`.
- Optional property: guard every check with `!is_null($this->container['name'])`.
- Allowed values of an inline enum: a `public const` for each value, a
  `get<Name>AllowableValues()` method, and an `in_array(..., true)` check (`Address.php`,
  `gender`).

Copy the message texts from an existing model, so reviews stay simple.

## Enums

An enum schema is a class that implements `EnumInterface`. Copy `OrderItemPaymentStatus.php`:

- a `public const` for each value
- `getAllowableEnumValues()`
- a static factory for each value, named like the value
- a constructor that takes the value, and `getValue()`

`ObjectSerializer` throws an `InvalidArgumentException` when it serializes a model with an enum
value that `getAllowableEnumValues()` does not list. It does not check the value when it reads a
response. So a new value of the specification must be in the enum class before a channel can send
it.

## Tests

Every model has a test in `tests/Client/Model/<Name>Test.php`.

- The test extends `AbstractApiModelTestCase` and has `#[CoversClass(<Name>::class)]`.
- `expectedInterface()` lists every property with its name, type, getter, setter and a flag for
  nullable. `it_has_expected_interface` is the test that uses it. Copy `AllowedValueTest.php`.
- Add a test for each validation rule you add. Name it by the behaviour, in snake_case.
- The flag is `true` when the property keeps `null` after a round trip, and `false` when it does
  not. A property with a non-null default is `false`, because the constructor replaces `null` with
  the default. `AllowedValue::getSort()` returns `?int`, yet `sort` is `false` in
  `AllowedValueTest.php`. Do not take the flag from the PHP type.
- A binary property (`\SplFileObject`) needs the type `\SplFileObject` in `expectedInterface()`
  (`InvoiceUploadTest.php`).
- Every enum has a test. Copy `OrderItemPaymentStatusTest.php`: `is_a_const_<VALUE>` and
  `it_can_be_constructed_for<VALUE>` for each value, and `it_has_correct_set_of_allowed_values`.
- A model with an inline enum has `it_has_correct_allowed_values_for_<property>`
  (`AddressTest.php`).
- `ModelStaticArraysTest.php` checks every model in the directory without a change: the five
  static arrays have the same keys, every named getter and setter exists, and every scalar
  property is read from its JSON name.

## The specification changed: how to change the client

1. Open the published OpenAPI file and read the schema at `components.schemas.<Name>`. Follow each
   `$ref` and each `allOf` part.
2. New schema: write `src/Client/Model/<Name>.php` and `tests/Client/Model/<Name>Test.php` by the
   rules above. Write a class for each new enum schema and each inline object too.
3. New or changed property: change the five static arrays, the constructor, the getter and the
   setter, `listInvalidProperties()`, and `expectedInterface()` in the test. Add a test for each
   new validation rule.
4. A schema that other schemas use as an `allOf` part: change every flat class that contains the
   part. Search the specification for the `$ref` to find them.
5. New enum value: add the constant, the static factory and the entry in
   `getAllowableEnumValues()`, and the tests for the value.
6. New seller event: add the value to `SellerEventTypeList` as in step 5, write the model, then do
   the steps of "Wiring a seller event" in the `AGENTS.md` of the repository root.
7. New endpoint: add a request class and a response class in `src/Client/Api/<Topic>/Request/` and
   `Response/`, and a method in the API class of that topic. The request class extends
   `AbstractScxApiRequest` and gives the URL, the HTTP method and the body. Copy
   `src/Client/Api/Order/Request/CreateOrderRequest.php` and `OrderApi::create()`. Add the tests
   in `tests/Client/Api/<Topic>/`.
8. A removed property or schema, or a property that changes from optional to required, breaks the
   channels that use it. Ask before you remove or narrow something.
9. Run `vendor/bin/phpunit --no-coverage`, `composer phpstan` and `composer phpcs-dry` in the
   repository root.
